# DroidDeck update research — November 5, 2026

This research informed the installer refresh. It separates upstream changes from Overwatch compatibility and from measurements that still need a phone. Repository baseline: OverwatchDroid `6b327ed`. DroidDeck source inspected: `7c5bf77f17dab0d9e080f12cb4db23aa3bfeab4f`.

## Runtime changes worth using

[DroidDeck 0.6.7](https://github.com/Droid-Deck/DroidDeck/releases/tag/0.6.7) added native Battle.net integration and reported lower Wine/FEX exception and process-query overhead. Those are upstream microbenchmarks, not Overwatch FPS measurements. [0.6.9](https://github.com/Droid-Deck/DroidDeck/releases/tag/0.6.9), published October 31, fixes dual-screen behavior, preserves FEX multiblock settings for .NET games, and extends low-memory compression to Battle.net. This supports keeping current runtime components rather than automatically replacing them with October binaries.

[DroidDeck-Proton 11-12.1](https://github.com/Droid-Deck/DroidDeck-Proton/releases/tag/DroidDeck-Proton-11-12.1), published November 3, carries the Blizzard-loader FEX changes introduced in 11-11.9 and additional FEX loading changes. The [11-11.9 notes](https://github.com/Droid-Deck/DroidDeck-Proton/releases/tag/DroidDeck-Proton-11-11.9) specifically document StarCraft Remastered. That is evidence that useful loader work is bundled; it is **not proof that the complete Overwatch fix is bundled or that Overwatch currently launches**.

The distinction matters: [GameNative/proton-wine #47](https://github.com/GameNative/proton-wine/pull/47) describes Wine-side ARM64EC mapping and PF/AF flag handling, alongside matching FEX requirements. The PR is closed without a merge. The `__wine_arm64ec_extended_eflags` marker was not found in the [ntdll export specification at the Wine pin listed by DroidDeck-Proton](https://github.com/The412Banner/proton-wine/blob/303894db765bad9936de9a532cb833dada939d58/dlls/ntdll/ntdll.spec). That source check alone does not establish what every release binary contains, especially with build-time patches. Therefore the October workaround remains available behind exact version/hash checks, including a new rootless route. No new Wine binary is supplied or claimed.

## GPU developments

[DD-Turnip v0.4.0](https://github.com/Droid-Deck/Drivers/releases/tag/DD-Turnip-v0.4.0), published November 2, includes updated Mesa plus Android and Linux driver halves. [v0.5.0](https://github.com/Droid-Deck/Drivers/releases/tag/DD-Turnip-v0.5.0), published November 4, is marked prerelease. Neither is a reason to force one driver on every Adreno generation. The setup leaves driver installation and selection to DroidDeck.

The [non-Adreno test project](https://github.com/The412Banner/droiddeck-nonadreno-drivers) reports Mali paths through MaliBridge, Venus and PanVK, Xclipse through RADV, and PowerVR through the system driver. Its test reports are for named devices and games; they do not validate Overwatch. As inspected on November 5, [DroidDeck PR #2029](https://github.com/Droid-Deck/DroidDeck/pull/2029) remained open and requested Mali device testing and an Adreno regression pass. Its [gamescope component release](https://github.com/Droid-Deck/DroidDeck/releases/tag/gamescope-3.16.29-pr2029-22b50d182) explicitly identifies itself as a PR test component, not an app release.

Implementation consequence: remove forced DX12 from the normal settings path, keep the selected GPU stack, offer an explicit DX11 trial, and describe non-Adreno support as experimental. A settings installer cannot supply Vulkan features missing from a phone driver.

## Installation and configuration

Current DroidDeck has both ARM and x86-64 Steam layouts, registered libraries, SD-card libraries, and a separate Battle.net prefix. The new setup discovers existing Overwatch config files across these locations and accepts explicit paths. Sources: [Steam root selection](https://github.com/Droid-Deck/DroidDeck/blob/7c5bf77f17dab0d9e080f12cb4db23aa3bfeab4f/app/src/main/java/com/droiddeck/launcher/session/SessionPrefs.kt), [library mounts](https://github.com/Droid-Deck/DroidDeck/blob/7c5bf77f17dab0d9e080f12cb4db23aa3bfeab4f/app/src/main/java/com/droiddeck/launcher/session/SteamLibraries.kt), [SD layout](https://github.com/Droid-Deck/DroidDeck/blob/7c5bf77f17dab0d9e080f12cb4db23aa3bfeab4f/app/src/main/java/com/droiddeck/launcher/session/GameStorage.kt), and [Battle.net prefix](https://github.com/Droid-Deck/DroidDeck/blob/7c5bf77f17dab0d9e080f12cb4db23aa3bfeab4f/app/src/main/java/com/droiddeck/launcher/runtime/BattleNet.kt).

DroidDeck still publishes the guest environment from Android-owned state. Editing only the guest JSON is not persistent. The rootless setup therefore leaves FEX environment changes to DroidDeck's per-game UI. The old ADB merge now preserves unrelated keys and refuses malformed JSON. See [GameEnvironmentStore](https://github.com/Droid-Deck/DroidDeck/blob/7c5bf77f17dab0d9e080f12cb4db23aa3bfeab4f/app/src/main/java/com/droiddeck/launcher/session/GameEnvironmentStore.kt). The proposed [per-game ntdll component, issue #675](https://github.com/Droid-Deck/DroidDeck/issues/675), remains open; modifying a Proton DLL still affects every game using that tool.

## Validation and remaining work

Automated tests exercise graphics preview/install/restore, configuration preservation, repeat installs, all profile/API combinations, library discovery, corrupt backups, concurrent changes, failed writes, legacy payload checks, exact-build runtime patching, full runtime restore and rollback after partial failure. The CI workflow runs the suite on Linux and macOS.

No Android hardware, Proton execution, multiplayer matches, thermal data, or new FPS measurements were used for this refresh. Before releasing it as tested, run the rootless flow in the current DroidDeck desktop on the original Thor, verify both runtime and graphics restores, then test the current Proton and exact-build fallback separately. For other phones, record exact GPU, Android/DroidDeck/Proton/FEX/driver versions, renderer, resolution, ten-minute frame pacing, and crash logs. Treat each non-Adreno result as device-specific.
